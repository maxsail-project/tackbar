# TackBar v0.6.3 — Usability & Maintenance Requirements

**Status:** Delivered
**Baseline:** TackBar v0.6.2 — Viewer & Admin Usability  
**Scope:** focused usability and maintenance corrections over the v0.6.2 baseline

---

## 1. Release objective

v0.6.3 collects small, reviewable mobile/tablet usability and maintenance
corrections without changing the validated v0.6.2 domain or Viewer model.

## 2. Delivered touch chart correction

`MetricChart` and the Individual Analysis dual-axis SOG + COG chart use one
Pointer Events selection path. A press inside the chart starts a temporary
selection, horizontal movement extends it, and release applies one local zoom
range to the chart's shared GPS/UTC X axis for touch, stylus and mouse input.

The chart captures the active pointer while selecting. Pointer cancellation,
uncaptured leave and capture loss clear the temporary selection without applying
a zoom. `touch-action: pan-y` remains scoped to the chart canvas so vertical
page scrolling remains available.

Each chart keeps its own presentation-only zoom and Reset action. Two Individual
Analysis Activity charts therefore remain independent.

## 3. Confirmed Admin Session microcopy requirement

On narrow Admin layouts, the redundant `shared` word makes the capability action
longer than necessary. The equivalent Admin Session links in `SailorDetail` and
the general `SessionCard` MUST display:

`Open session`

The capability URL, availability rules, routing and all Session/capability
semantics remain unchanged. Personal TackBar's existing `Open Session` action
is not part of this correction.

## 4. CI maintenance

The production deployment workflow uses `actions/checkout@v5` for its release
tooling checkout. Deployment behavior and release validation rules remain
unchanged.

## 5. Session Viewer selector email presentation

Activity selectors MUST shorten an identity that falls back to a Sailor email
by hiding everything after the first `@`, while retaining the `@` character:

- `maxi@example.com` → `maxi@`;
- `maxi+vakaros@example.com` → `maxi+vakaros@`.

The underlying Sailor email, Activity ID, option value and selection semantics
remain unchanged. Existing Activity identity precedence remains unchanged,
including Boat and Sailor name fallbacks. This increment does not redesign
`Sailor.name` presentation, and it does not truncate email identities in maps,
tables, summaries, replay or charts.

## 6. Admin operational navigation

The Admin top-level navigation MUST present sections in the operational order:

`Ingestions → Sailors → Sessions`

After successful Admin access, `Ingestions` MUST be the initially visible
section. This changes presentation/workflow ordering only; all three sections,
their loading behavior, manual mailbox review, APIs and persistence semantics
remain unchanged.

## 7. Delivered SailorDetail Session history hierarchy

The embedded Session history cards under `SailorDetail → Sessions` MUST use a
clear mobile-first presentation hierarchy. Sailing date/time is the primary
visual identity, with the capability status shown in the card header and
visually separated from Session access.

The cards MUST retain the Activity count and Session expiry as explicit,
readable metadata, using correct `Activity` / `Activities` singular/plural
wording. When existing capability and ACTIVE-consent conditions permit access,
the `Open session` action MUST retain its existing availability and exact href
semantics in a separate Session access block.

This is a presentation-only reorganization. Top-level Admin Session cards are
out of scope; Session capability, consent, expiry, API and persistence
semantics remain unchanged.

## 8. Preserved semantics and non-goals

v0.6.3 preserves:

- the shared Analysis Window and filtered sample set;
- map, Summary, replay and shared `playbackTime` behavior;
- normal comparison-chart behavior;
- one dual-axis individual SOG + COG chart per selected Activity;
- SOG/COG axes, colors, missing-value behavior and COG circular semantics;
- Session capability behavior, consent behavior and Session lifetime semantics;
- frontend/backend API contracts and JSON/filesystem persistence.

This release does not add persisted zoom, saved segments, new metrics, new
replay behavior, backend changes, API changes, database changes, layout
redesign or a broader Admin redesign.

## 9. Validation

Focused temporal zoom, Individual Analysis and Admin frontend checks passed,
including 21 AdminPage tests and 11 selector/Session Viewer tests. Frontend
typecheck, production build and `git diff --check` also passed. Production
deployment and production smoke validation are not claimed by this requirements
document.
