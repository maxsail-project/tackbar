# Session Viewer

This specification owns accepted collaborative Viewer behavior. Its separately marked unresolved findings are not delivered guarantees. [The index](index.md) defines the documentation route.

## Current contract

### Access and selected Activities

- Original `/s/<token>` and temporary `/q/<token>` URLs open the same collaborative Session Viewer using their respective backend APIs. Temporary access identifies itself and has no action to delegate another share. The Viewer receives only content permitted by the current shared access checks. [Access and Consent](access-and-consent.md) owns capability, expiry and ACTIVE-only authorization; [Domain and Sessions](domain-and-sessions.md) owns Activity and Session identity, matching and lifetime.
- One Primary Activity is selected; one distinct Activity from the same visible Session may be selected as Comparison. The selected unit is its stable Activity ID, including when a Sailor has several Activities. Selectors use human-readable Sailor, Boat and time context; an email fallback is shortened to its local part plus `@` **in the selectors only**. Selection changes the existing Viewer rather than opening an Activity detail flow.
- At most the selected pair participates in Summary, VS, signal charts, Individual Analysis and maneuver comparison. Additional currently visible Session Activities may appear as neutral, low-emphasis **fleet context on the map only**. Their tracks are limited to the current Analysis Window, their markers share `playbackTime`, and they do not expand map-fit bounds or gain analytical colors or telemetry rows. Tapping a contextual marker reveals its identity and an explicit **Compare** action, which preserves Primary and replaces Comparison. An unavailable contextual track does not break the selected pair's debrief. No fleet ranking or N-way analytics is implied.

### Shared Analysis Window and replay

- The Viewer uses one ephemeral GPS/UTC Analysis Window for the selected Activities. With one Activity, its initial available range is that Activity's time range. With two, the initial comparable range is the intersection of their time ranges; when no positive overlap exists, the Viewer reports that no comparable GPS/UTC interval exists rather than inventing one. A user may narrow or reset the common window within the available range. It changes the mapped selected segments, Summary, charts, VS, event display and replay availability without cutting or persisting an Activity or Saved Segment.
- The SOG timeline is the Analysis Window selection surface. Horizontal drag selects a narrower shared range, and its Reset restores the full available range. It has integrated play/pause, scrubber and speed controls. A range change keeps `playbackTime` within the selected range and stops playback. Timeline event markers remain separate from a drag gesture. This selection is distinct from any chart-local interaction.
- Replay has one `playbackTime` shared by Primary, Comparison and contextual map markers. Supported speeds are x1, x2, x5 and x10 GPS seconds per real second. Play/pause and scrubbing are temporal controls; device sample rate does not set speed. Map positions may interpolate between surrounding samples for display without creating track data. The map's fixed instantaneous GPS time, SOG, COG, HEEL and TRIM telemetry is independent of the selected chart view and remains unavailable where a sensor value is missing.

### Map, Summary and metric selection

- The map is the primary spatial context. It distinguishes Primary and Comparison, shows their current-window tracks and synchronized replay positions, and fits the selected pair. Fleet context remains visually subordinate. Map telemetry does not duplicate selected maneuver Loss or the selected chart metric.
- The Summary compares each selected Activity over the same Analysis Window in this order: **Distance; Avg SOG; Max SOG; Dominant COG; Median HEEL +; Median HEEL −; Median TRIM +; Median TRIM −**. Missing metrics display unavailable rather than being inferred. Summary Distance is the accumulated normalized `dist` after the first included sample, rounded to whole metres; the first included sample contributes zero because its stored increment can precede the window. Other distance presentations retain their existing units.
- Avg SOG is accumulated distance divided by elapsed time between the first and last selected samples when a valid interval exists; Max SOG is the maximum finite canonical SOG. Dominant COG is the most frequent north-centered circular course bin, with correct 0°/360° wrap; it is not an arithmetic heading mean. The four signed HEEL/TRIM values are **independent time-weighted medians** of positive and negative sensor values. Zero belongs to neither group. They use valid adjacent UTC intervals clipped to the Analysis Window, omit nonpositive intervals and gaps over 1.5 seconds, and choose the first value reaching half the represented time without interpolation. A sign group without represented time is unavailable. No sign-to-sailing-side interpretation is assigned.
- The selector offers **VS** by default, then SOG, COG, HEEL and TRIM. VS is a view, not a sailing metric. A selected time-series metric is the same for both Activities on a common GPS/UTC axis. Summary remains visible independently of that choice.

### Charts and distributions

- The main SOG and COG charts are native SVG with contextual raw and foreground smoothed signals. SOG smoothing is a centered, time-weighted trend; COG smoothing is centered, time-weighted and circular-safe. Both raw and smoothed COG paths break at the 0°/360° wrap rather than drawing false full-height transitions. The main HEEL chart is a signed stepped representation from UTC-aligned, two-second, time-weighted buckets, with gaps over 1.5 seconds left unbridged; TRIM is a signed raw trace with presentation-only point reduction. The shared Analysis Window and replay cursor apply to all four. These main charts have no chart-local zoom, Reset or tooltip control. Visual smoothing, buckets and point reduction do not change canonical telemetry, Summary, VS or replay values.
- VS shows time-weighted SOG histogram, circular COG rose, signed-linear HEEL semicircle and signed TRIM boxplot for the shared window. Adjacent canonical sample intervals contribute represented time clipped to the window; nonpositive intervals and gaps over 1.5 seconds do not add time. Coverage is valid represented time divided by window duration, independently for each Activity and metric. Below the accepted 80% VS coverage threshold, an Activity is omitted from that distribution with a clear metric-specific reason; another eligible Activity can still be shown. Distribution percentages refer to valid represented time, not sample counts.
- SOG uses aligned P/C bins; COG uses north-centered circular sectors so values across 0°/360° remain near each other. HEEL uses signed-linear 2° bins in the accepted `[-20°, +20°)` domain; out-of-domain represented time lowers HEEL coverage. TRIM uses time-weighted empirical Q1, median and Q3, Tukey 1.5×IQR whiskers and time-weighted outlier percentages on a shared signed P/C axis. These distributions are descriptive and do not assign a favorable sailing meaning to a value or sign.
- **Individual Analysis** stays within the Viewer. Each selected Activity has its own native-SVG SOG+COG chart on a common UTC X axis, with SOG and circular COG axes, raw/smoothed roles and the shared replay cursor. Directly after it, that Activity has a separate HEEL×SOG represented-time density map; Primary and Comparison are not overlaid in one density map. The density uses canonical intervals clipped to the Analysis Window, a signed HEEL axis, a shared 0-based SOG domain and per-Activity percentages with a common P/C intensity scale. Low coverage is warned about rather than automatically hiding otherwise usable density. Neither Individual chart has local zoom, Reset or a separate playback clock.

### Maneuver interaction and Session context

- Inside the collapsible **MANEUVERS** section, directly below its heading and above the event table, a compact evidence summary identifies each selected role with available analytics and an explicit backend `detector_mode`: **P · HIGH evidence** / **P · LOW evidence**, and the equivalent **C** label when Comparison is selected. It reuses P/C colors and wraps on narrow screens. Labels describe maneuver detection evidence, never overall Activity or track quality; they are not inferred from provider, device or sensor inventory. Available zero-event analytics retains its indicator; unavailable, loading, error and missing-mode results have no evidence label and retain existing status presentation. Selection changes update the owning P/C indicator through both original and temporary shared Viewer routes.
- The summary's discreet, neutral information icon has a 44px touch target, an accessible name and a visible keyboard focus indicator. Touch/click, Enter or Space toggles a compact popover; Escape or an outside interaction dismisses it. It is anchored to the control where CSS anchor positioning is supported, with a viewport-constrained centered fallback. The popover is titled **Maneuver detection evidence** and explains HIGH as HDG-based detection with available HEEL/COG/SOG support, LOW as COG/SOG-based detection, and that neither level guarantees detection accuracy or indicates overall track quality. Its secondary lines carry that limitation and **ΔHDG = heading change · ΔCOG = course change**. Evidence adds no table column, per-row marker or selector label.
- A collapsible Maneuvers table presents one row per detected event belonging to a selected Activity whose **center** lies inside the current Analysis Window. It can sort chronological time in either direction and exposes Time, Activity, Loss distance/time, Recovery, entry/minimum/exit SOG, mode-specific direction change and duration, with clear unavailable states and narrow-screen horizontal scrolling. Primary and Comparison markers on the SOG timeline identify events without adding another analytical clock.
- The direction column identifies **ΔHDG** for HIGH events and **ΔCOG** for LOW events, including mixed-mode P/C comparisons. Separate `heading_change_deg` and `course_change_deg` API fields preserve their respective angle meanings; the other angle is null. HIGH retains its calculated peak HDG rate in °/s and timestamp; LOW's peak fields are null. SOG metrics remain independently nullable. The backend chooses the mode and supplies provenance; the Viewer does not infer headings or choose a detector. An available zero-event result shows the existing empty state; insufficient evidence retains the unavailable state. Filtering, event navigation, row/timeline selection and P/C ordering apply equally to both modes.
- Selecting a table row or timeline marker highlights the event and moves the shared `playbackTime` to its center without changing the Analysis Window. Timeline-marker selection also requests role-aware map focus above the fixed telemetry overlay. Whether table-row selection must issue that same focus request is unresolved below. Selection clears when its Activity or the window no longer includes it. Only an explicitly selected event adds Loss distance, equivalent Loss time and Recovery beneath the owning Activity's compact window summary; independent replay movement does not alter that detail. Compact window summaries retain Avg SOG, distance and whole-degree Dominant COG without a visible `COG` label. [Analytics](analytics.md) owns event detection, metric definitions and artifact validity.
- Directly below the Maneuvers table, one profile chart uses the established analytics selector styling for its implemented SOG, COG and HEEL options and compares independent Primary and Comparison typical curves on a shared signal-specific scale and fixed `−25s … t=0 … +25s` axis. SOG retains absolute knots; COG shows oriented relative turn degrees, not geographic course; HEEL shows nonnegative `|HEEL| (°)` magnitude rather than signed inclination. The event center remains `t=0`. A two-ended touch and keyboard angular band control starts at 40°–100°, moves in 5° steps within 0°–180°, and filters both roles by the same contextual `|ΔCOG|`. The chart distinguishes raw median and post-median smoothed strokes, breaks where fewer than three eligible maneuvers support an offset, and prioritizes counts of maneuvers in the Analysis Window and used for the selected signal. Exclusions appear when relevant, with missing-context or insufficient-population states retained. In SOG mode only, three compact SOG Maneuver Insights indicators show Entry SOG, Minimum SOG and Exit SOG from supported raw median curves, P/C values and neutral readings when available. They sit side by side on tablet and desktop and stack on narrow mobile screens; maneuver counts remain by the chart. Supported center-relative Profile recovery has P/C-colored chart markers and `P +Ns` / `C +Ns` labels when established, plus one compact summary distinguishing recovered, not reached by +25s and unavailable. It is separate from event-table Recovery. Filtering and signal selection never change the event table, replay or Analysis Window. [Analytics](analytics.md) owns the filter, aggregation, insight, recovery and axis semantics.
- Across SOG, COG and HEEL Maneuver Insights, missing metric values and unavailable P/C comparisons display `—`. Explanatory unavailable states and SOG Profile recovery status wording remain unchanged.
- In COG mode, three compact Insights cards show supported raw-median Turn angle, center-relative Turn midpoint and Turn duration (10–90%) with P/C values, sailor colors and neutral differences. They share the SOG Insights layout: one row on tablet and desktop, stacked on narrow mobile screens. The COG chart has no duration interval, endpoint markers or duration labels. Missing Insights values and comparisons display `—`; explanatory unavailable states remain unchanged. COG mode has no SOG Profile recovery. [Analytics](analytics.md) defines support and crossing rules.
- In HEEL mode, three compact Insights cards show Entry HEEL, HEEL variation and Exit HEEL from supported raw `|HEEL|` medians. Variation is the signed change in central typical magnitude from Entry, not a side transition or peak. Cards use P/C colors and neutral differences; missing Insights values and comparisons display `—`. They share the responsive three-card layout. The HEEL chart uses a zero-based shared degree axis and softer raw traces; HEEL mode has no Profile recovery. [Analytics](analytics.md) defines support and windows.
- The original and temporary Viewer Session heading uses persisted **City > Country > nothing** plus sailing date, with date-only fallback, separately from Activity selector identity. City and country are never concatenated and region is not a fallback. The map's compact historical/modelled conditions cue selects the persisted hourly sample nearest the Analysis Window midpoint, choosing the earlier sample on an equal-distance tie; replay movement alone does not change that cue. The cue omits unavailable atmospheric values and is absent for marine-only context. Opening it shows available wind, temperature, cloud, wave and UTC sample-time detail identified as historical/modelled, without changing the map or replay. The accepted optional-gust wording is unresolved below. [Session Context](session-context.md) owns location, weather/marine provenance and availability.
- The Viewer remains a responsive phone/tablet debrief screen with explicit loading, unavailable and no-overlap states. The frontend consumes backend APIs; it does not read JSON or track files directly.
- The original and temporary Viewer public headers provide an About panel without changing Viewer state or route. Where release metadata is available, the exact deployed tag and release family appear beneath the public logo and within About; unavailable metadata is omitted rather than inferred. Admin, consent screens and the shared-link-required fallback are outside this public About surface. [Completed #116](https://github.com/maxsail-project/tackbar/issues/116) records the accepted placement.

### Unresolved implementation discrepancy

**Medium — maneuver table map focus.** [V7-VIEW-02](../v0.7-collaborative-debrief-analytics-requirements.md) says selecting either a table row or timeline marker issues role-aware map focus. `frontend/src/pages/SessionViewerPage.tsx` currently requests focus for a timeline marker but passes `focusMap = false` for a table row. Focused tests establish the focus-request helper and event selection, but do not close this difference. Product review should confirm whether both selection surfaces retain the documented focus contract or whether the governing requirement should change; this specification does not choose between them.

**Medium — compact weather gust.** [V7-CTX-05](../v0.7-collaborative-debrief-analytics-requirements.md) specifies an optional parenthesized gust in the compact Viewer chip. `frontend/src/utils/historicalConditions.ts` formats only wind direction, wind speed and air temperature; `frontend/src/utils/historicalConditions.test.ts` and `frontend/src/components/HistoricalConditionsControl.test.tsx` expressly expect no compact gust even when one is present. The expanded detail does show available gust. Confirm whether the accepted compact-gust contract should be implemented or explicitly revised; this specification does not claim it is delivered.
