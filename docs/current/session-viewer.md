# Session Viewer

This specification owns accepted collaborative Viewer behavior. Its separately marked unresolved findings are not delivered guarantees. [The index](index.md) defines the documentation route.

## Current contract

### Access and selected Activities

- Original `/s/<token>` and temporary `/q/<token>` URLs open the same collaborative Session Viewer using their respective backend APIs. Temporary access identifies itself and has no action to delegate another share. The Viewer receives only content permitted by the current shared access checks. [Access and Consent](access-and-consent.md) owns capability, expiry and ACTIVE-only authorization; [Domain and Sessions](domain-and-sessions.md) owns Activity and Session identity, matching and lifetime.
- One Primary Activity is selected; one distinct Activity from the same visible Session may be selected as Comparison. The selected unit is its stable Activity ID, including when a Sailor has several Activities. The compact selectors identify an Activity by nonblank Boat sail number, then Boat name, then Boat class; otherwise by its descriptive Device label, original Device name, then Sailor name/email/ID. A Sailor email fallback is shortened to its local part plus `@`. Each selector label retains the compact UTC time range. Only identical complete labels receive `#1`, `#2`, etc., ordered by sailing start and then Activity ID across the full visible Session Activity set. Summary column headers use the same compact identity and any suffix earned by an identical complete selector label, without the UTC range. Labels stay stable across selected roles and Comparison filtering. This numbering is presentation-only; other Viewer Activity identities remain unchanged. Selection changes the existing Viewer rather than opening an Activity detail flow.
- On initial opening of an original or temporary Session Viewer, Primary defaults to the currently visible Activity with the greatest **sum of pairwise GPS/UTC metadata interval overlaps** with every other visible Activity. Each pair contributes `max(0, min(end_i, end_j) − max(start_i, start_j))` to both Activities; overlap shared with two others counts twice. Equal scores resolve by longer positive individual interval duration, then ascending Activity ID. Invalid or nonpositive intervals contribute zero score and duration; one visible Activity is selected alone, and no visible Activity retains the empty state. Comparison starts unset. This ranking runs only for the initial default of the opened Session; later manual P/C selections remain authoritative through ordinary rerenders, track loading, metadata refreshes and Viewer interactions. The rule does not select a Comparison or alter selector ordering.
- At most the selected pair participates in Summary, VS, signal charts, Individual Analysis and maneuver comparison. Additional currently visible Session Activities may appear as neutral, low-emphasis **fleet context on the map only**. Their tracks are limited to the current Analysis Window, their markers share `playbackTime`, and they do not expand map-fit bounds or gain analytical colors or telemetry rows. Tapping a contextual marker reveals its identity and an explicit **Compare** action, which preserves Primary and replaces Comparison. An unavailable contextual track does not break the selected pair's debrief. No fleet ranking or N-way analytics is implied.

### Shared Analysis Window and replay

- The Viewer uses one ephemeral GPS/UTC Analysis Window for the selected Activities. With one Activity, its initial available range is that Activity's time range. With two, the initial comparable range is the intersection of their time ranges; when no positive overlap exists, the Viewer reports that no comparable GPS/UTC interval exists rather than inventing one. A user may narrow or reset the common window within the available range. It changes the mapped selected segments, Summary, charts, VS, event display and replay availability without cutting or persisting an Activity or Saved Segment.
- The SOG timeline is the Analysis Window selection surface. Horizontal drag selects a narrower shared range, and its Reset restores the full available range. It has integrated play/pause, scrubber and speed controls. A range change keeps `playbackTime` within the selected range and stops playback. Tapping a timeline event marker remains separate from a drag gesture. This selection is distinct from any chart-local interaction.
- The Viewer reconstructs ephemeral **Session Starts** from every valid type `3` (`RACE_START`, timer zero) VKX observation of every currently authorized visible Session Activity, regardless of Primary/Comparison selection. Timer `START` (type `1`), `RACE_END` (type `4`) and other timer events do not affect inference; no timer cycles are reconstructed. Each Activity candidate retains its source timestamp, Activity identity and stable source order for equal timestamps. Candidates from distinct Activities synchronize when their full UTC span is at most the centrally configured 3-second default tolerance, with at most one candidate per Activity and the median UTC timestamp as representative. Groups less than the centrally configured 300-second default distinct-start gap compete by distinct-Activity support, then later median on a tie. With multiple contributing Activities, only groups supported by at least two distinct Activities become Starts; when only one Activity contributes candidates, its timer-zero candidates may become Starts after the same separation rule. Selected winning Starts receive stable chronological `S1`, `S2`… labels before Analysis Window filtering. These labels describe inferred timer-zero context, not official race starts or persisted Race/Session records.
- Only Starts with median timestamps inside the current Analysis Window, including either endpoint, appear on the SOG timeline. Each uses a thin Slate (`#52636b`) full-height guide with matching compact outlined, keyboard-accessible S1/S2 labels at its top and bottom and larger hit areas confined to those control zones; the middle remains available for range brushing. Start controls take precedence over nearby maneuver markers. Tapping either control stops replay, seeks the shared GPS clock to that exact UTC timestamp and requests map focus on the Primary boat position at that time using the existing maneuver-focus camera behavior; repeated taps request focus again. If the Primary position is unavailable, seeking still works and map focus is skipped. The Analysis Window, map bearing, zoom conventions and selected Activities remain unchanged. A horizontal drag beginning on either Start control selects an Analysis Window range at the existing drag threshold and does not seek to the Start or request map focus. Activity selection and Reset filter the same complete Session-level Start set again; existing no-overlap and unavailable replay states remain in force.
- The shared read also exposes only each currently visible Activity's ordered `0x05` PIN/BOAT observations (timestamp, endpoint type and recorded coordinates) under the same original or temporary Session capability checks. For every inferred Start, each visible Activity independently contributes its latest PIN and BOAT observations at or before that Start, with no age cutoff. PIN and BOAT consensus are independent; observations within the centrally configured 3 m tolerance form compatible groups, each Activity counts once, and the largest supported endpoint groups determine recorded endpoints. Where complete endpoints exist, the displayed pair uses the greatest-length admissible recorded PIN–BOAT combination, without averaging or changing source observations. Inferred pairs are ephemeral and retain `Pn–Bn` identity per Start. The map alone displays these endpoints and a thin segment; incomplete pairs show only the available endpoint. It displays only Start configurations inside the Analysis Window, inclusive of both edges. Equivalent complete pairs collapse visually only when both endpoints are within 3 m and circular bearing difference is below the centrally configured 10 degrees; the lowest-numbered currently visible Start labels the single displayed pair. Parallel displaced lines remain distinct. No official committee line, Race, Boat or Sailor identity is inferred.
- The Analysis Window header keeps its title and secondary “Drag SOG to select interval” instruction inline, with replay speed and Reset at right. On narrow screens the title stays intact while the instruction may wrap naturally; control touch targets remain unchanged.
- Beneath the Analysis Window timeline, a compact table compares the entire shared window with columns **P/C | Avg SOG | Max SOG | Distance | Dom COG | Maneuvers**. It shows one Primary row and a Comparison row only when selected, with functional P/C colors and existing metric formatting. Each Maneuvers value counts that Activity's detected event centers inside the current Analysis Window, independently of Selected Maneuvers and Maneuver Profiles filtering. Available analytics with no such events shows `0`; unavailable, loading, error or unresolved analytics shows `—`. The table has shared headings and remains compact without horizontal scrolling.
- Replay has one `playbackTime` shared by Primary, Comparison and contextual map markers. Replay starts at x5; selectable speeds are x1, x2, x5 and x10 GPS seconds per real second. The chosen speed persists through maneuver selection, Activity changes and Analysis Window changes. Play/pause and scrubbing are temporal controls; device sample rate does not set speed. Map positions may interpolate between surrounding samples for display without creating track data. The map's fixed instantaneous GPS time, SOG, COG, HEEL and TRIM telemetry is independent of the selected chart view and remains unavailable where a sensor value is missing.

### Map, Summary and metric selection

- The map is the primary spatial context. It distinguishes Primary and Comparison, shows their current-window tracks and synchronized replay positions, and fits the selected pair. Fleet context remains visually subordinate. Map telemetry does not duplicate selected maneuver Loss or the selected chart metric.
- The map's compact **TWD** control replaces geographic DIR in both original and temporary Viewers. The automatic reference selects the persisted modelled-weather sample with usable finite wind direction nearest the current Analysis Window midpoint in UTC, even outside the window or temporally distant; an equal-distance tie chooses earlier UTC. It retains original unrounded direction, source kind, UTC sample time and available provider provenance. The camera uses circular nearest-5° rounding for presentation. If no valid source exists, the control shows `TWD —` and the camera is North-up without asserting 000° wind. Replay time alone does not change the reference.
- The compact ±5° controls create an ephemeral **Manual · Viewer** correction, starting from the rounded automatic TWD or operational North-up when unavailable (+5° → 005°, −5° → 355°). The correction persists across Analysis Window changes and detail dismissal. In manual mode, **Manual · Viewer** and Reset appear only inside the expanded TWD detail; Reset restores the current automatic reference or unavailable/North-up state without closing the detail. The collapsed control retains its direction value and ±5° buttons without a manual status or Reset row. The accessible TWD detail distinguishes modelled source, nearest valid wind sample to window midpoint, source UTC time and provider, original direction, rounded automatic direction and Viewer correction; manual-only and unavailable states remain explicit. The compact TWD value toggles its detail, and the free area of the expanded TWD header provides an accessible close button. An outside interaction anywhere in the Viewer, including map pan or zoom, closes the expanded TWD or Weather detail; interaction inside the active detail keeps it open. Opening one detail closes the other. The ±5° and Reset buttons retain their actions without dismissing their detail. Dismissing detail does not change the correction or source observation.
- A narrow **TWS** value chip sits beside TWD on the same map-control row in original and temporary Viewers. Its automatic reference independently selects the persisted modelled-weather sample with finite, nonnegative 10 m wind speed nearest the current Analysis Window midpoint in UTC; an equal-distance tie chooses earlier UTC. Samples outside the window or temporally distant remain eligible. It retains original unrounded speed, source kind, UTC sample time and available weather-provider provenance. Missing or invalid values show `TWS --`; zero is valid. The collapsed chip shows only `TWS` and `--` or the automatic or manual speed rounded to whole knots; no adjustment controls or manual status appear until it opens an anchored detail. That detail has one horizontal `− / TWS value / +` row with touch-friendly buttons that change the ephemeral Viewer reference immediately by 1 kt, starting from rounded automatic TWS when available. From unavailable, the first `+` gives `1 kt` and the first `−` gives `0 kt`; further decreases stop at zero. There is no numeric input or Apply action. The expanded detail identifies original modelled TWS, source UTC time and provider separately from the displayed correction. When a manual reference is active, **Manual · Viewer** and Reset appear together in the expanded detail footer. The manual reference survives Analysis Window changes and is neither sent to the backend nor persisted; Reset clears only TWS and restores the current automatic reference or `TWS --` when unavailable. Replay time alone does not change this reference. TWS does not affect TWD or map bearing. Gust appears only in the existing Weather detail, never in TWS. TWS detail shares TWD and Weather mutual exclusion and outside/map interaction dismissal; closing it leaves an applied TWS unchanged.
- Effective TWD controls map bearing. A deliberate two-finger twist on touch or conventional right-button drag or Ctrl+drag on desktop rotates the map continuously as a Viewer TWD correction; one-finger and ordinary left-button drag still pan, and wheel and pinch zoom remain. On gesture completion, the bearing normalizes across 0°/360° and snaps to the nearest 5° under the existing rounding convention. If that value equals effective TWD before the gesture (manual, rounded modelled, or operational North-up when unavailable), the prior Automatic/Manual mode and committed bearing remain; otherwise it becomes the existing ephemeral Manual · Viewer correction, with the map and compact TWD value synchronized. Cancelled gestures restore the prior bearing without correction, and programmatic fit, focus, replay, window or TWD changes do not create corrections. Keyboard rotation remains disabled; there is no independent geographic camera mode. P/C and contextual boat markers retain geographic course orientation relative to the camera. Inferred Start endpoints retain their geographic positions and circular `Pn`/`Bn` markers. The separate historical/modelled conditions cue keeps its descriptive sample-selection behavior and original values. [Session Context](session-context.md) owns the modelled-source meaning; [Analytics](analytics.md) owns the current analytical boundary.
- The Summary compares each selected Activity over the same Analysis Window in this order: **Distance; Avg SOG; Max SOG; Dominant COG; Median HEEL +; Median HEEL −; Median TRIM +; Median TRIM −**. Missing metrics display unavailable rather than being inferred. Summary Distance is the accumulated normalized `dist` after the first included sample, rounded to whole metres; the first included sample contributes zero because its stored increment can precede the window. Other distance presentations retain their existing units.
- Avg SOG is accumulated distance divided by elapsed time between the first and last selected samples when a valid interval exists; Max SOG is the maximum finite canonical SOG. Dominant COG is the most frequent north-centered circular course bin, with correct 0°/360° wrap; it is not an arithmetic heading mean. The four signed HEEL/TRIM values are **independent time-weighted medians** of positive and negative sensor values. Zero belongs to neither group. They use valid adjacent UTC intervals clipped to the Analysis Window, omit nonpositive intervals and gaps over 1.5 seconds, and choose the first value reaching half the represented time without interpolation. A sign group without represented time is unavailable. No sign-to-sailing-side interpretation is assigned.
- Track Analysis follows Summary and its selector offers **VS** by default, then SOG, COG, HEEL and TRIM. VS is a view, not a sailing metric. A selected time-series metric is the same for both Activities on a common GPS/UTC axis. Summary remains visible independently of that choice.

### Charts and distributions

- The main SOG and COG charts are native SVG with contextual raw and foreground smoothed signals. SOG smoothing is a centered, time-weighted trend; COG smoothing is centered, time-weighted and circular-safe. Both raw and smoothed COG paths break at the 0°/360° wrap rather than drawing false full-height transitions. The main HEEL chart is a signed stepped representation from UTC-aligned, two-second, time-weighted buckets, with gaps over 1.5 seconds left unbridged; TRIM is a signed raw trace with presentation-only point reduction. The shared Analysis Window and replay cursor apply to all four. These main charts have no chart-local zoom, Reset or tooltip control. Visual smoothing, buckets and point reduction do not change canonical telemetry, Summary, VS or replay values.
- VS shows time-weighted SOG histogram, circular COG rose, signed-linear HEEL semicircle and signed TRIM boxplot for the shared window. Adjacent canonical sample intervals contribute represented time clipped to the window; nonpositive intervals and gaps over 1.5 seconds do not add time. Coverage is valid represented time divided by window duration, independently for each Activity and metric. Below the accepted 80% VS coverage threshold, an Activity is omitted from that distribution with a clear metric-specific reason; another eligible Activity can still be shown. Distribution percentages refer to valid represented time, not sample counts.
- SOG uses aligned P/C bins; COG uses north-centered circular sectors so values across 0°/360° remain near each other. HEEL uses signed-linear 2° bins in the accepted `[-20°, +20°)` domain; out-of-domain represented time lowers HEEL coverage. TRIM uses time-weighted empirical Q1, median and Q3, Tukey 1.5×IQR whiskers and time-weighted outlier percentages on a shared signed P/C axis. These distributions are descriptive and do not assign a favorable sailing meaning to a value or sign.
- **Individual Analysis** stays within the Viewer. Each selected Activity has its own native-SVG SOG+COG chart on a common UTC X axis, with SOG and circular COG axes, raw/smoothed roles and the shared replay cursor. Directly after it, that Activity has a separate HEEL×SOG represented-time density map; Primary and Comparison are not overlaid in one density map. The density uses canonical intervals clipped to the Analysis Window, a signed HEEL axis, a shared 0-based SOG domain and per-Activity percentages with a common P/C intensity scale. Low coverage is warned about rather than automatically hiding otherwise usable density. Neither Individual chart has local zoom, Reset or a separate playback clock.

### Maneuver interaction and Session context

- Inside the collapsed-by-default **Maneuver Analysis** section, directly below its heading and above the event table, a compact evidence summary identifies each selected role with available analytics and an explicit backend `detector_mode`: **P · HIGH evidence** / **P · LOW evidence**, and the equivalent **C** label when Comparison is selected. It reuses P/C colors and wraps on narrow screens. Labels describe maneuver detection evidence, never overall Activity or track quality; they are not inferred from provider, device or sensor inventory. Available zero-event analytics retains its indicator; unavailable, loading, error and missing-mode results have no evidence label and retain existing status presentation. Selection changes update the owning P/C indicator through both original and temporary shared Viewer routes.
- The summary's discreet, neutral information icon has a 44px touch target, an accessible name and a visible keyboard focus indicator. Touch/click, Enter or Space toggles a compact popover; Escape or an outside interaction dismisses it. It is anchored to the control where CSS anchor positioning is supported, with a viewport-constrained centered fallback. The popover is titled **Maneuver detection evidence** and explains HIGH as HDG-based detection with available HEEL/COG/SOG support, LOW as COG/SOG-based detection, and that neither level guarantees detection accuracy or indicates overall track quality. Its secondary lines carry that limitation and **ΔHDG = heading change · ΔCOG = course change**. Evidence adds no table column, per-row marker or selector label.
- The collapsed-by-default **Maneuver Analysis** section directly follows Analysis Window; its event table presents one row per detected event belonging to a selected Activity whose **center** lies inside the current Analysis Window. It can sort chronological time in either direction and exposes Time, Activity, Loss distance/time, Recovery, entry/minimum/exit SOG, mode-specific direction change and duration, with clear unavailable states and narrow-screen horizontal scrolling. Primary and Comparison markers on the SOG timeline identify events without adding another analytical clock.
- The direction column identifies **ΔHDG** for HIGH events and **ΔCOG** for LOW events, including mixed-mode P/C comparisons. Separate `heading_change_deg` and `course_change_deg` API fields preserve their respective angle meanings; the other angle is null. HIGH retains its calculated peak HDG rate in °/s and timestamp; LOW's peak fields are null. SOG metrics remain independently nullable. The backend chooses the mode and supplies provenance; the Viewer does not infer headings or choose a detector. An available zero-event result shows the existing empty state; insufficient evidence retains the unavailable state. Filtering, event navigation, row/timeline selection and P/C ordering apply equally to both modes.
- A compact **Selected Maneuvers** strip sits between Map and Analysis Window with a visible heading and stable space for two single-line records, including empty states. The latest selected event appears first and the previous distinct selection second; selecting another event shifts the former first record down, while reselecting the current event leaves history unchanged. Both timeline-marker and table-row selection feed these records, highlight the current event in the table, navigate the one shared `playbackTime` to the event center and request focus on the owning Primary or Comparison boat above the fixed telemetry overlay. Repeated selection requests focus again without changing history. Up to two read-only P/C-colored map highlights show the owning Activity's supported trajectory within ±25 seconds of each selected maneuver center, clipped to the shared Analysis Window and available track evidence. Invalid coordinates, nonpositive intervals and sample gaps over 1.5 seconds are never bridged; a selection without supported line geometry has no highlight. Each uses a subtle white halo under a P/C-colored trajectory line; both selections share the same style and stay geographically fixed during replay without adding map interactions or altering fitting. Both records clear whenever the shared Analysis Window or Primary/Comparison Activity selection changes, even if events remain eligible. Ordinary replay movement does not change the records.
- Each selected record uses the P/C functional color. The shared compact headings are **MANEUVERS**, Loss, Rec, SOG (in/min/out), and Δ (°). Both rows show individual-event UTC time, Loss distance and equivalent time, Recovery, Entry/Minimum/Exit SOG as a triplet with one trailing `kt` when a value is available, and the signed direction-change angle in degrees, without horizontal scrolling. The compact Δ value omits HDG/COG provenance; the full Maneuver Analysis event table retains that detail and duration. Missing displayed values remain unavailable without invented units, and accessible metric descriptions retain their meanings. No HIGH/LOW marker appears in these records. [Analytics](analytics.md) owns event detection, metric definitions and artifact validity.
- The expanded-by-default **Maneuver Profiles** section follows Track Analysis and precedes Individual Analysis. Its single profile chart uses the established analytics selector styling for its implemented SOG, COG and HEEL options and compares independent Primary and Comparison typical curves on a shared signal-specific scale and fixed `−25s … t=0 … +25s` axis. SOG retains absolute knots; COG shows oriented relative turn degrees, not geographic course; HEEL shows nonnegative `|HEEL| (°)` magnitude rather than signed inclination. The event center remains `t=0`. A two-ended touch and keyboard angular band control starts at 40°–100°, moves in 5° steps within 0°–180°, and filters both roles by the same contextual `|ΔCOG|`. The chart distinguishes raw median and post-median smoothed strokes, breaks where fewer than three eligible maneuvers support an offset, and prioritizes counts of maneuvers in the Analysis Window and used for the selected signal. Exclusions appear when relevant, with missing-context or insufficient-population states retained. In SOG mode only, a compact Maneuver Insights table shows Entry SOG, Minimum SOG and Exit SOG from supported raw median curves, with aligned P, C and a visually blank, accessibly named comparison row; maneuver counts remain by the chart. Supported center-relative Profile recovery has P/C-colored chart markers and `P +Ns` / `C +Ns` labels when established, plus one compact summary distinguishing recovered, not reached by +25s and unavailable. It is separate from event-table Recovery. Filtering and signal selection never change the event table, replay or Analysis Window. [Analytics](analytics.md) owns the filter, aggregation, insight, recovery and axis semantics.
- Across SOG, COG and HEEL Maneuver Insights, each comparison cell shows `Similar` within its existing signal-specific tolerance, otherwise `P +X<unit>` or `C +X<unit>` for the larger underlying numeric value. SOG retains its configured knot tolerance; COG and HEEL retain one-decimal equivalence. Differences use one decimal and the metric unit (SOG `kt`, COG angle `°`, COG time `s`, HEEL `°`). Missing metric values and unavailable P/C comparisons display `—`. The comparison row has no visible label. These differences are descriptive, not performance judgements. Explanatory unavailable states and SOG Profile recovery status wording remain unchanged.
- The Maneuver Profiles disclosure and its controls remain available whether Maneuver Analysis is expanded or collapsed.
- In COG mode, the Maneuver Insights table shows supported raw-median Turn angle, center-relative Turn midpoint and Turn duration (10–90%) with P/C values, sailor colors and neutral differences in the same aligned rows. The COG chart has no duration interval, endpoint markers or duration labels. Missing Insights values and comparisons display `—`; explanatory unavailable states remain unchanged. COG mode has no SOG Profile recovery. [Analytics](analytics.md) defines support and crossing rules.
- In HEEL mode, the Maneuver Insights table shows Entry HEEL, HEEL variation and Exit HEEL from supported raw `|HEEL|` medians. Variation is the signed change in central typical magnitude from Entry, not a side transition or peak. P/C rows use functional colors and retain neutral differences; missing Insights values and comparisons display `—`. The shared three-column layout remains visible on phone, tablet and desktop, with long headings allowed to wrap. The HEEL chart uses a zero-based shared degree axis and softer raw traces; HEEL mode has no Profile recovery. [Analytics](analytics.md) defines support and windows.
- The original and temporary Viewer Session heading uses persisted **City > Country > nothing** plus sailing date, with date-only fallback, separately from Activity selector identity. City and country are never concatenated and region is not a fallback. The map's compact historical/modelled Weather cue selects the persisted hourly sample nearest the Analysis Window midpoint, choosing the earlier sample on an equal-distance tie; replay movement alone does not change that cue. It shows whole-degree Celsius temperature and, when justified, a monochrome condition icon; it shows no wind direction, speed, TWS or Gust. Supported WMO `weather_code` values map to sun (0–1), cloud-sun (2), cloud (3), or cloud-rain (51, 53, 55–57, 61, 63, 65–67, 80–82). An unsupported code shows no icon and does not fall back to cloud cover. Only when the code is absent or invalid, valid cloud cover in 0–20%, above 20% and below 80%, or 80–100% maps to sun, cloud-sun or cloud respectively; cloud cover never implies rain. Without usable temperature, meaningful weather or marine context retains a `Weather` cue, optionally with a justified icon. Without a justified icon, usable temperature appears alone; an empty or unusable sample has no cue. Opening the cue preserves the existing original wind, Gust, temperature, cloud, wave, UTC sample-time and provider detail, without changing the map or replay. [Session Context](session-context.md) owns location, weather/marine provenance and availability.
- The Viewer remains a responsive phone/tablet debrief screen with explicit loading, unavailable and no-overlap states. The frontend consumes backend APIs; it does not read JSON or track files directly.
- The original and temporary Viewer public headers provide an About panel without changing Viewer state or route. Where release metadata is available, the exact deployed tag and release family appear beneath the public logo and within About; unavailable metadata is omitted rather than inferred. Admin, consent screens and the shared-link-required fallback are outside this public About surface. [Completed #116](https://github.com/maxsail-project/tackbar/issues/116) records the accepted placement.
