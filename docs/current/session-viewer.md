# Session Viewer

This specification owns accepted collaborative Viewer behavior. Its separately marked unresolved findings are not delivered guarantees. [The index](index.md) defines the documentation route.

## Current contract

### Access and selected Activities

- Original `/s/<token>` and temporary `/q/<token>` URLs open the same collaborative Session Viewer using their respective backend APIs. Temporary access identifies itself and has no action to delegate another share. The Viewer receives only content permitted by the current shared access checks. [Access and Consent](access-and-consent.md) owns capability, expiry and ACTIVE-only authorization; [Domain and Sessions](domain-and-sessions.md) owns Activity and Session identity, matching and lifetime.
- One Primary Activity is selected; one distinct Activity from the same visible Session may be selected as Comparison. The selected unit is its stable Activity ID, including when a Sailor has several Activities. The compact selectors identify an Activity by nonblank Boat sail number, then Boat name, then Boat class; otherwise by its descriptive Device label, original Device name, then Sailor name or a backend-derived email-local-part-plus-`@` display fallback. Full Sailor emails and internal Sailor IDs are absent from original and temporary shared Session details. The backend supplies the count of distinct visible Sailors for the Viewer header. Each selector label retains the compact UTC time range. Only identical complete labels receive `#1`, `#2`, etc., ordered by sailing start and then Activity ID across the full visible Session Activity set. Summary column headers use the same compact identity and any suffix earned by an identical complete selector label, without the UTC range. Labels stay stable across selected roles and Comparison filtering. This numbering is presentation-only; other Viewer Activity identities remain unchanged. Selection changes the existing Viewer rather than opening an Activity detail flow.
- On initial opening of an original or temporary Session Viewer, Primary defaults to the currently visible Activity with the greatest **sum of pairwise GPS/UTC metadata interval overlaps** with every other visible Activity. Each pair contributes `max(0, min(end_i, end_j) − max(start_i, start_j))` to both Activities; overlap shared with two others counts twice. Equal scores resolve by longer positive individual interval duration, then ascending Activity ID. Invalid or nonpositive intervals contribute zero score and duration; one visible Activity is selected alone, and no visible Activity retains the empty state. Comparison starts unset. This ranking runs only for the initial default of the opened Session; later manual P/C selections remain authoritative through ordinary rerenders, track loading, metadata refreshes and Viewer interactions. The rule does not select a Comparison or alter selector ordering.
- At most the selected pair participates in Summary, VS, signal charts, Individual Analysis and maneuver comparison. Additional currently visible Session Activities may appear as neutral, low-emphasis **fleet context on the map only**. Their tracks are limited to the current Analysis Window, their markers share `playbackTime`, and they do not expand map-fit bounds or gain analytical colors or telemetry rows. Tapping a contextual marker reveals its identity and an explicit **Compare** action, which preserves Primary and replaces Comparison. An unavailable contextual track does not break the selected pair's debrief. No fleet ranking or N-way analytics is implied.

### Shared Analysis Window and replay

- The Viewer uses one ephemeral GPS/UTC Analysis Window for the selected Activities. With one Activity, its initial available range is that Activity's time range. With two, the initial comparable range is the intersection of their time ranges; when no positive overlap exists, the Viewer reports that no comparable GPS/UTC interval exists rather than inventing one. A user may narrow or reset the common window within the available range. It changes the mapped selected segments, Summary, charts, VS, event display and replay availability without cutting or persisting an Activity or Saved Segment.
- The SOG timeline is the Analysis Window selection surface. Horizontal drag selects a narrower shared range, and its Reset restores the full available range. It has integrated play/pause, scrubber and speed controls. A range change keeps `playbackTime` within the selected range and stops playback. Tapping a timeline event marker remains separate from a drag gesture. This selection is distinct from any chart-local interaction.
- The Viewer reconstructs ephemeral **Session Starts** from every valid type `3` (`RACE_START`, timer zero) VKX observation of every currently authorized visible Session Activity, regardless of Primary/Comparison selection. Timer `START` (type `1`), `RACE_END` (type `4`) and other timer events do not affect inference; no timer cycles are reconstructed. Each Activity candidate retains its source timestamp, Activity identity and stable source order for equal timestamps. Candidates from distinct Activities synchronize when their full UTC span is at most the centrally configured 3-second default tolerance, with at most one candidate per Activity and the median UTC timestamp as representative. Groups less than the centrally configured 300-second default distinct-start gap compete by distinct-Activity support, then later median on a tie. With multiple contributing Activities, only groups supported by at least two distinct Activities become Starts; when only one Activity contributes candidates, its timer-zero candidates may become Starts after the same separation rule. Selected winning Starts receive stable chronological `S1`, `S2`… labels before Analysis Window filtering. These labels describe inferred timer-zero context, not official race starts or persisted Race/Session records.
- Only Starts with median timestamps inside the current Analysis Window, including either endpoint, appear on the SOG timeline. Each uses a thin Slate (`#52636b`) full-height guide with matching compact outlined, keyboard-accessible S1/S2 labels at its top and bottom and larger hit areas confined to those control zones; the middle remains available for range brushing. Start controls take precedence over nearby maneuver markers. Tapping either control stops replay, seeks the shared GPS clock to that exact UTC timestamp and requests map focus on the Primary boat position at that time using the existing maneuver-focus camera behavior; repeated taps request focus again. If the Primary position is unavailable, seeking still works and map focus is skipped. The Analysis Window, map bearing, zoom conventions and selected Activities remain unchanged. A horizontal drag beginning on either Start control selects an Analysis Window range at the existing drag threshold and does not seek to the Start or request map focus. Activity selection and Reset filter the same complete Session-level Start set again; existing no-overlap and unavailable replay states remain in force.
- The shared read also exposes only each currently visible Activity's ordered `0x05` PIN/BOAT observations (timestamp, endpoint type and recorded coordinates) under the same original or temporary Session capability checks. For every inferred Start, each visible Activity independently contributes its latest PIN and BOAT observations at or before that Start, with no age cutoff. PIN and BOAT consensus are independent; observations within the centrally configured 3 m tolerance form compatible groups, each Activity counts once, and the largest supported endpoint groups determine recorded endpoints. Where complete endpoints exist, the displayed pair uses the greatest-length admissible recorded PIN–BOAT combination, without averaging or changing source observations. Inferred pairs are ephemeral and retain `Pn–Bn` identity per Start. The map alone displays these endpoints and a thin segment; incomplete pairs show only the available endpoint. It displays only Start configurations inside the Analysis Window, inclusive of both edges. Equivalent complete pairs collapse visually only when both endpoints are within 3 m and circular bearing difference is below the centrally configured 10 degrees; the lowest-numbered currently visible Start labels the single displayed pair. Parallel displaced lines remain distinct. No official committee line, Race, Boat or Sailor identity is inferred.
- Per approved [#220](https://github.com/maxsail-project/tackbar/issues/220) (D1–D3, D5, D6, D8), the Viewer derives ephemeral **race shortcuts** from the same authorized timer read, which also carries `RACE_END` (type `4`) observations ([Access and Consent](access-and-consent.md)). For each inferred Session Start `Sn`, whose inference above is unchanged, the race end is the latest valid `RACE_END` observation among every currently visible Session Activity, regardless of Primary/Comparison selection, strictly after `Sn` and strictly before the next Start (without an upper bound for the last Start). A Start without such an end has no race: no end is inferred, and countdowns without `RACE_START` never become races. A race reuses its Start's number (the race of `S2` is `R2`), so numbering may skip. Its window is `[Sn − 5 min, race end]`; the 5-minute pre-start margin is a code-configurable constant. Race shortcuts filter the Analysis Window only: they are not persisted, not official races and not Race or Session records, and they never trim, split or alter track data.
- Per approved #220 (D4-rev, D6, D9), a compact native single-select with the accessible name **Race** and no visible label sits in the Analysis Window header immediately left of the replay speed control, in the same visual style and height with a 44px target. Its options and closed state read only `All` and `R1`…`RN` (no times or durations), listing each race whose window overlaps the available range; when no race qualifies, the control is absent without an empty state. Selecting `Rn` sets the shared Analysis Window for the selected Activities, including GPX Activities without timer data, through the existing window-change path: clamped to the available range, `playbackTime` kept inside, playback stopped and selected maneuver records cleared, with Primary/Comparison unchanged; as a change from outside the Wind segment list it resets the Wind Segments filter to All. The control shows `Rn` while the Analysis Window equals that race's clamped bounds and returns to `All` after any other window change (timeline drag, including one beginning on a Start control, Reset, Wind segment selection or Activity reconciliation); a Start tap, which does not change the window, keeps it. Selecting `All` restores the full available range through the same handler as Reset. Original and temporary Viewers behave identically; the selection is ephemeral and is neither persisted nor sent to the backend.
- Per approved #218 (D4), the SOG timeline line of each selected Activity breaks at every gap without joining its recorded endpoints, and each gap of the full canonical Primary or Comparison track that overlaps the Analysis Window by a positive duration is highlighted as unavailable evidence: a hatched band clipped to the window, edged with the Activity color at the top for Primary and at the bottom for Comparison. The bands do not intercept pointer input, so range dragging, markers, Session Start controls and scrubbing behave as before. Directly below the Analysis Window table, one small notice appears only while the window overlaps a gap of the selected Primary and/or Comparison by a positive duration, including a window boundary inside a gap and a window entirely inside one; touching a gap endpoint is not overlap. One line per affected role reads **P · No GPS data for 1m04s in this window** (or **C …**) with the missing GPS time inside the window in the Analysis Window duration format, adding ` (N gaps)` when more than one gap overlaps. It disappears with no overlap; there is no global banner, repeated notice or detail flow.
- The Analysis Window header keeps its title and secondary “Drag SOG to select interval” instruction inline, with the Race control when shown (#220), replay speed and Reset at right. On narrow screens the title stays intact while the instruction may wrap naturally; control touch targets remain unchanged. While the Race control is shown on narrow screens, the instruction sits on its own line below the intact title and the header controls use tighter spacing so that they stay on one row without overflow at 320–375px.
- Beneath the Analysis Window timeline, a compact table compares the entire shared window with columns **P/C | Avg SOG | Max SOG | Distance | Dom COG | Maneuvers**. It shows one Primary row and a Comparison row only when selected, with functional P/C colors and existing metric formatting. Each Maneuvers value counts that Activity's detected event centers inside the current Analysis Window, independently of Selected Maneuvers and Maneuver Profiles filtering. Available analytics with no such events shows `0`; unavailable, loading, error or unresolved analytics shows `—`. Its Avg SOG and Distance follow the gap-aware Summary rules below. The table has shared headings and remains compact without horizontal scrolling.
- Replay has one `playbackTime` shared by Primary, Comparison and contextual map markers. Replay starts at x5; selectable speeds are x1, x2, x5 and x10 GPS seconds per real second. The chosen speed persists through maneuver selection, Activity changes and Analysis Window changes. Play/pause and scrubbing are temporal controls; device sample rate does not set speed. Map positions may interpolate between surrounding samples for display without creating track data. The map's fixed instantaneous GPS time, SOG, COG, HEEL and TRIM telemetry is independent of the selected chart view and remains unavailable where a sensor value is missing.
- Per approved [#218](https://github.com/maxsail-project/tackbar/issues/218) (D5, D7), a **gap** is any positive adjacent canonical UTC interval strictly longer than the shared, code-configurable 10-second threshold, in Activities of any source, derived by the Viewer from the samples. While `playbackTime` is strictly inside a gap of an Activity, that Activity has no interpolated replay position and never moves along the cross-gap chord: its marker stays at its last recorded sample before the gap, greyed, with a **No GPS data** label, and its SOG, COG, HEEL and TRIM telemetry shows `—`. The gap is detected on the full canonical track, so it also applies when an Analysis Window boundary falls inside the gap. At the exact UTC times of the gap endpoints, replay is normal. Other Activities, the shared clock, playback and speed are unaffected; map focus requested at a time inside the Primary gap is skipped as for an unavailable position. Contextual fleet markers follow the same greyed last-sample state.

### Map, Summary and metric selection

- The map is the primary spatial context. It distinguishes Primary and Comparison, shows their current-window tracks and synchronized replay positions, and fits the selected pair. Fleet context remains visually subordinate. Map telemetry does not duplicate selected maneuver Loss or the selected chart metric.
- Per approved [#218](https://github.com/maxsail-project/tackbar/issues/218) (D3, D4), every recorded track polyline, Primary, Comparison and fleet context, stops and restarts at the recorded endpoints of each gap; a run with a single recorded sample draws no line. For each gap of the Primary or Comparison whose two recorded endpoints are inside the current Analysis Window, the map draws one thinner, translucent, dashed connector in that Activity's color between those endpoints. It is a presentation-only unknown-path geometric chord, never recorded track, sailed distance or a replay path. A compact **Gap** control at the chord midpoint (44px touch target, accessible name stating the role and missing GPS time, keyboard focusable) opens a popup titled **P · GPS gap** or **C · GPS gap** that states the missing GPS time, the **net geometric displacement between recorded endpoints** in whole metres, and that the dashed line is a straight chord between the recorded endpoints and the path sailed is unknown. It shows no coordinates. Opening it closes a contextual Activity popup and vice versa; Escape on the control, the popup close button or a map tap closes it. Map-fit bounds are unchanged.
- The map's compact **TWD** control replaces geographic DIR in both original and temporary Viewers. The automatic reference selects the persisted modelled-weather sample with usable finite wind direction nearest the current Analysis Window midpoint in UTC, even outside the window or temporally distant; an equal-distance tie chooses earlier UTC. It retains original unrounded direction, source kind, UTC sample time and available provider provenance. The camera uses circular nearest-5° rounding for presentation. If no valid source exists, the control shows `TWD —` and the camera is North-up without asserting 000° wind. Replay time alone does not change the reference.
- The compact ±5° controls create an ephemeral **Manual · Viewer** correction, starting from the rounded automatic TWD or operational North-up when unavailable (+5° → 005°, −5° → 355°). The correction persists across Analysis Window changes and detail dismissal. In manual mode, **Manual · Viewer** and Reset appear only inside the expanded TWD detail; Reset restores the current automatic reference or unavailable/North-up state without closing the detail. The collapsed control retains its direction value and ±5° buttons without a manual status or Reset row. The accessible TWD detail distinguishes modelled source, nearest valid wind sample to window midpoint, source UTC time and provider, original direction, rounded automatic direction and Viewer correction; manual-only and unavailable states remain explicit. The compact TWD value toggles its detail, and the free area of the expanded TWD header provides an accessible close button. An outside interaction anywhere in the Viewer, including map pan or zoom, closes the expanded TWD or Weather detail; interaction inside the active detail keeps it open. Opening one detail closes the other. The ±5° and Reset buttons retain their actions without dismissing their detail. Dismissing detail does not change the correction or source observation.
- A narrow **TWS** value chip sits beside TWD on the same map-control row in original and temporary Viewers. Its automatic reference independently selects the persisted modelled-weather sample with finite, nonnegative 10 m wind speed nearest the current Analysis Window midpoint in UTC; an equal-distance tie chooses earlier UTC. Samples outside the window or temporally distant remain eligible. It retains original unrounded speed, source kind, UTC sample time and available weather-provider provenance. Missing or invalid values show `TWS --`; zero is valid. The collapsed chip shows only `TWS` and `--` or the automatic or manual speed rounded to whole knots; no adjustment controls or manual status appear until it opens an anchored detail. That detail has one horizontal `− / TWS value / +` row with touch-friendly buttons that change the ephemeral Viewer reference immediately by 1 kt, starting from rounded automatic TWS when available. From unavailable, the first `+` gives `1 kt` and the first `−` gives `0 kt`; further decreases stop at zero. There is no numeric input or Apply action. The expanded detail identifies original modelled TWS, source UTC time and provider separately from the displayed correction. When a manual reference is active, **Manual · Viewer** and Reset appear together in the expanded detail footer. The manual reference survives Analysis Window changes and is neither sent to the backend nor persisted; Reset clears only TWS and restores the current automatic reference or `TWS --` when unavailable. Replay time alone does not change this reference. TWS does not affect TWD or map bearing. Gust appears only in the existing Weather detail, never in TWS. TWS detail shares TWD and Weather mutual exclusion and outside/map interaction dismissal; closing it leaves an applied TWS unchanged.
- Effective TWD controls map bearing. A deliberate two-finger twist on touch or conventional right-button drag or Ctrl+drag on desktop rotates the map continuously as a Viewer TWD correction; one-finger and ordinary left-button drag still pan, and wheel and pinch zoom remain. On gesture completion, the bearing normalizes across 0°/360° and snaps to the nearest 5° under the existing rounding convention. If that value equals effective TWD before the gesture (manual, rounded modelled, or operational North-up when unavailable), the prior Automatic/Manual mode and committed bearing remain; otherwise it becomes the existing ephemeral Manual · Viewer correction, with the map and compact TWD value synchronized. Cancelled gestures restore the prior bearing without correction, and programmatic fit, focus, replay, window or TWD changes do not create corrections. Keyboard rotation remains disabled; there is no independent geographic camera mode. P/C and contextual boat markers retain geographic course orientation relative to the camera. Inferred Start endpoints retain their geographic positions and circular `Pn`/`Bn` markers. The separate historical/modelled conditions cue keeps its descriptive sample-selection behavior and original values. [Session Context](session-context.md) owns the modelled-source meaning; [Analytics](analytics.md) owns the current analytical boundary.
- The Summary compares each selected Activity over the same Analysis Window in this order: **Distance; Avg SOG; Max SOG; Dominant COG; Median HEEL +; Median HEEL −; Median TRIM +; Median TRIM −**. Missing metrics display unavailable rather than being inferred. Summary Distance is the accumulated normalized `dist` after the first included sample, rounded to whole metres; the first included sample contributes zero because its stored increment can precede the window. Per approved #218 D8, a sample whose interval from the previous canonical sample is a gap contributes zero as well: its stored cross-gap `dist` is an endpoint chord, not sailed distance. Other distance presentations retain their existing units.
- Avg SOG is that within-run Summary Distance divided by the covered within-run time inside the Analysis Window — the elapsed time between the first and last selected samples minus every gap interval between them (#218 D8) — when it is positive. Gap time overlapping the window, including the portion before the first or after the last selected sample when a window boundary falls inside a gap, is unavailable rather than slow sailing. A window entirely inside a gap has no selected samples and shows its metrics as unavailable. Tracks without gaps keep identical values. Max SOG is the maximum finite canonical SOG. Dominant COG is the most frequent north-centered circular course bin, with correct 0°/360° wrap; it is not an arithmetic heading mean. The four signed HEEL/TRIM values are **independent time-weighted medians** of positive and negative sensor values. Zero belongs to neither group. They use valid adjacent UTC intervals clipped to the Analysis Window, omit nonpositive intervals and gaps over 1.5 seconds, and choose the first value reaching half the represented time without interpolation. A sign group without represented time is unavailable. No sign-to-sailing-side interpretation is assigned.
- Track Analysis follows Summary and its selector offers **VS** by default, then SOG, COG, HEEL and TRIM. VS is a view, not a sailing metric. A selected time-series metric is the same for both Activities on a common GPS/UTC axis. Summary remains visible independently of that choice.

### Charts and distributions

- The main SOG and COG charts are native SVG with contextual raw and foreground smoothed signals. SOG smoothing is a centered, time-weighted trend; COG smoothing is centered, time-weighted and circular-safe. Both raw and smoothed COG paths break at the 0°/360° wrap rather than drawing false full-height transitions. The main HEEL chart is a signed stepped representation from UTC-aligned, two-second, time-weighted buckets, with gaps over 1.5 seconds left unbridged; TRIM is a signed raw trace with presentation-only point reduction. The shared Analysis Window and replay cursor apply to all four. Per approved #218, every raw and smoothed SOG, COG and TRIM path, including the Individual SOG+COG chart, also breaks across a gap (an adjacent interval over 10 seconds) without joining its endpoints; where a path already breaks at a shorter interval (SOG and COG smoothing, HEEL buckets: 1.5 seconds) that stricter rule remains. These main charts have no chart-local zoom, Reset or tooltip control. Visual smoothing, buckets and point reduction do not change canonical telemetry, Summary, VS or replay values.
- VS shows time-weighted SOG histogram, circular COG rose, signed-linear HEEL semicircle and signed TRIM boxplot for the shared window. Adjacent canonical sample intervals contribute represented time clipped to the window; nonpositive intervals and gaps over 1.5 seconds do not add time. Coverage is valid represented time divided by window duration, independently for each Activity and metric. Below the accepted 80% VS coverage threshold, an Activity is omitted from that distribution with a clear metric-specific reason; another eligible Activity can still be shown. Distribution percentages refer to valid represented time, not sample counts.
- SOG uses aligned P/C bins; COG uses north-centered circular sectors so values across 0°/360° remain near each other. HEEL uses signed-linear 2° bins in an adaptive symmetric domain `[-D°, +D°)` shared by P and C: `D` is the larger, across the displayed Activities, of the |HEEL| below which 95% of each Activity's valid HEEL time lies, rounded up to the 2° bin width and clamped to 10°–40°, widened in 2° steps if an Activity eligible at 40° would otherwise be unavailable. Valid HEEL time outside `[-D°, +D°)` is excluded and lowers HEEL coverage. TRIM uses time-weighted empirical Q1, median and Q3, Tukey 1.5×IQR whiskers and time-weighted outlier percentages on a shared signed P/C axis. These distributions are descriptive and do not assign a favorable sailing meaning to a value or sign.
- **Individual Analysis** stays within the Viewer. Each selected Activity has its own native-SVG SOG+COG chart on a common UTC X axis, with SOG and circular COG axes, raw/smoothed roles and the shared replay cursor. Directly after it, that Activity has a separate HEEL×SOG represented-time density map; Primary and Comparison are not overlaid in one density map. The density uses canonical intervals clipped to the Analysis Window, a signed HEEL axis, a shared 0-based SOG domain and per-Activity percentages with a common P/C intensity scale. Low coverage is warned about rather than automatically hiding otherwise usable density. Neither Individual chart has local zoom, Reset or a separate playback clock.

### Maneuver interaction and Session context

- Per approved [#38](https://github.com/maxsail-project/tackbar/issues/38) increment #38.1 (D2, D5–D9, D11), one collapsed-by-default **Start Analysis** section (header **START ANALYSIS**) directly follows Analysis Window and precedes Maneuver Analysis and Points of Sail in original and temporary Viewers. It appears only when at least one Session Start is inferred and is otherwise absent; its header, Expand/Collapse control, typography and table style follow Maneuver Analysis. Its body shows the caption **Starts inferred from race timer · times UTC** and one summary table (accessible name “Start summary”) listing chronologically, per approved #38 D15, only the inferred Session Starts whose gun lies inside the current Analysis Window, either endpoint included (the same rule as the SOG timeline Start labels); when the Session has inferred Starts but none inside the window, the section stays visible and the text **No inferred Start in the Analysis Window** replaces the table. Values remain derived from the full canonical tracks, not from the window. If the activated Start leaves the window, its activation is cleared and its detailed table hidden; it stays inactive if the window later includes it again. Rows: per Start, a P row and, only while a Comparison is selected, a C row directly below it. Per approved #38 D16 (superseding the #38.1 column labels and order), columns are an untitled P/C column first (visually hidden header text “Activity”, P/C colours), **Start** (the `S<n>` label on a first line and the gun's UTC `HH:MM:SS` time, smaller, on a second line, spanning that Start's rows), **Cross** (signed compact seconds with one decimal and the recorded SOG at the crossing, for example `+7.4s · 4.6 kt`; `+7.4s · —` when the crossing has no recorded SOG; `—` without a crossing; per D24 a crossing beyond either recorded end within the 10 m configurable tolerance adds ` ↔` with accessible text “beyond the recorded end”), **Dist** (signed, one decimal, for example `+15.8 m`), **Line** (integer, for example `87%`, possibly negative or above 100), per approved #38 increment #38.3 (D20) **Fav** (spanning that Start's rows like **Start**: `PIN` when PIN is the favoured end, `BOAT` when BOAT is, `Square` when the line bias rounds to 0°, `—` without a complete line or an effective TWD; accessible name such as “Favoured end PIN”; neutral, with no verdict label or highlighting, and horizontal scrolling on narrow screens is accepted) and **Note** (spanning that Start's rows); the Note column, header and cells, is rendered only when at least one listed Start has a note. Units are in the cells for the whole table and the headers carry none, following the #204 convention (space before `kt` and `m`, typographic minus for displayed negatives); unavailable values read `—`. The value cells' accessible names spell the units (for example “Cross +7.4 seconds, SOG 4.6 knots”, “Distance to the line at the gun +15.8 metres”, “Line position at the gun 87 percent”). While the table is shown, a help line below the caption reads **Cross: time and SOG when crossing the line · Dist, Line: position at the gun**. [Analytics](analytics.md) defines the values: the gun is the Start's inferred timer zero, distances and positions refer to that Start's inferred PIN–BOAT line and are computed over each selected Activity's full canonical track, and without a complete line for that Start every value reads `—`. **Dist** (at the gun) is positive behind the line and negative beyond it, **Cross** is negative when the crossing happened before the gun, and **Line** runs from PIN 0 % to BOAT 100 %, reading below 0 or above 100 outside the ends. Cross, Dist and Line remain numeric readings: never labelled OCS, ranked, bolded or coloured to mark a better boat. Fav names the geometric end per D23 and is not a verdict. The Note reads **⚠ Ends +<duration>** in the Analysis Window compact duration format (for example `⚠ Ends +1m24s`) when the Start's #220 paired `RACE_END` is at most 180 seconds after the gun and is otherwise empty; it states the fact only, infers no cause or validity, and that Start's values are computed as for any other. Activating a Start — a pointer on either of its rows, or its keyboard-accessible Start button with the accessible name “Move replay to S<n> gun at HH:MM:SS UTC, inferred from race timer” — highlights its rows (the button reports `aria-pressed`) and performs the same navigation as a Session Start label tap: replay stops, the shared GPS clock seeks to the gun (clamped to the current Analysis Window like any seek) and map focus is requested on the Primary boat; the Analysis Window, map bearing, zoom and selected Activities are unchanged and the page does not scroll. Limitations: distances are measured from the GPS antenna, not the bow, so a value within about ±2 m of the line is a reading, not an over-the-line verdict; the course side follows the standard PIN-left convention, so a line laid with the committee boat at the port end inverts the signs and is not detected; Starts and lines are inferred, not official. The section is ephemeral and read-only, with no persistence, backend change or new access path.
- Per approved [#38](https://github.com/maxsail-project/tackbar/issues/38) increment #38.2 (D3, D4, D10, D11) as revised by D17–D19, while a Start is activated in the summary table, a **detailed table** for that Start appears below the summary table inside the Start Analysis body; it is absent while no Start is activated, activating another Start switches it, and collapsing the section keeps the activated Start (expanding shows the same detail again). It is headed by one line with the Start label and the gun's UTC time (for example **S2 10:10:00 UTC**); per #38.3 (D20), when the Start has a complete inferred line the heading continues with `· Line <length> m` (integer metres) and, with an effective TWD, `· <PIN|BOAT> +<bias>° (<advantage> m) · TWD <source>` (integer degrees and metres; for example **S2 10:10:00 UTC · Line 287 m · PIN +8° (38 m) · TWD Modelled**), or `· Square · TWD <source>` when the bias rounds to 0°, where the source reads **Modelled** or **Manual · Viewer** as in Points of Sail; without an effective TWD only the line length is added, and without a line the heading is unchanged and has the accessible name “S<n> details around the gun”. Rows are indicators and columns are offsets around the gun: a first column with the indicator label and unit (**SOG (kt)**, **Dist (m)**, **HDG (°)**, **COG (°)**, **Heel (°)**, **Lead (m)**; visually hidden header text “Indicator”), an untitled P/C column (visually hidden header text “Activity”), then one column per offset in compact seconds, per D17 **−15s**, **−5s**, **0s** (the gun), **+5s** and **+15s**, with the typographic minus. Per D18 the **HDG (°)** row appears only when at least one selected Activity records HDG somewhere in its canonical track; an Activity without HDG still reads `—` in that row, and **COG (°)** always appears. Per indicator there is a P row and, only while a Comparison is selected, a C row directly below it in P/C colours, the indicator label spanning both; the single **Lead (m)** row (D21 calculation and D25 short label, superseding the D19 signed Windward P–C presentation), shown only while a Comparison is selected, has no P/C marker. Values read SOG with one decimal, Dist signed with one decimal (same sign as **Dist** in the summary), HDG and COG as integer degrees 0–359, Heel as a signed integer as stored and Lead as the further-upwind boat's P/C-coloured letter and integer metres (for example `P 8`, `C 6`), or `Level` when the absolute along-axis separation is under 1 m; unavailable values — no recorded sample within the tolerance, a gap, no recorded HDG, no complete start line for Dist, or no effective TWD or a missing sample for Lead — read `—`. Lead uses the same effective TWD as Points of Sail, including a **Manual · Viewer** correction, with no fallback axis; it is a neutral position reading, not gain/loss or ranking. [Analytics](analytics.md) defines the values. There are no Δ rows and no bold, colour or label marking a better value. Both Start Analysis tables centre headers and values as in the Analysis Window Summary; the detailed indicator label column stays left-aligned. COG mode has no SOG Profile recovery. [Analytics](analytics.md) defines support and crossing rules.
- In HEEL mode, the Maneuver Insights table shows Entry HEEL, HEEL variation and Exit HEEL from supported raw `|HEEL|` medians. Variation is the signed change in central typical magnitude from Entry, not a side transition or peak. P/C rows use functional colors and retain neutral differences; missing Insights values and comparisons display `—`. The shared three-column layout remains visible on phone, tablet and desktop, with long headings allowed to wrap. The HEEL chart uses a zero-based shared degree axis and softer raw traces; HEEL mode has no Profile recovery. [Analytics](analytics.md) defines support and windows.
- The original and temporary Viewer Session heading uses persisted **City > Country > nothing** plus sailing date, with date-only fallback, separately from Activity selector identity. City and country are never concatenated and region is not a fallback. The map's compact historical/modelled Weather cue selects the persisted hourly sample nearest the Analysis Window midpoint, choosing the earlier sample on an equal-distance tie; replay movement alone does not change that cue. It shows whole-degree Celsius temperature and, when justified, a monochrome condition icon; it shows no wind direction, speed, TWS or Gust. Supported WMO `weather_code` values map to sun (0–1), cloud-sun (2), cloud (3), or cloud-rain (51, 53, 55–57, 61, 63, 65–67, 80–82). An unsupported code shows no icon and does not fall back to cloud cover. Only when the code is absent or invalid, valid cloud cover in 0–20%, above 20% and below 80%, or 80–100% maps to sun, cloud-sun or cloud respectively; cloud cover never implies rain. Without usable temperature, meaningful weather or marine context retains a `Weather` cue, optionally with a justified icon. Without a justified icon, usable temperature appears alone; an empty or unusable sample has no cue. Opening the cue preserves the existing original wind, Gust, temperature, cloud, wave, UTC sample-time and provider detail, without changing the map or replay. [Session Context](session-context.md) owns location, weather/marine provenance and availability.
- The Viewer remains a responsive phone/tablet debrief screen with explicit loading, unavailable and no-overlap states. The frontend consumes backend APIs; it does not read JSON or track files directly.
- The original and temporary Viewer public headers provide an About panel. Below the public logo, the release family appears as plain text when available. The exact configured version is an underlined link with an external-link icon, and the version itself is the link's accessible name. If the version is absent or blank, the header shows a **Release notes** link regardless of family availability. About shows available release identity and always offers a **Release notes** link. Both links open the [latest published GitHub Release](https://github.com/maxsail-project/tackbar/releases/latest) in a new tab without sending a referrer or granting access to the original window. The Viewer route, Analysis Window, selected Activities and replay state are preserved. Admin, consent screens and the shared-link-required fallback are outside this public About surface.
