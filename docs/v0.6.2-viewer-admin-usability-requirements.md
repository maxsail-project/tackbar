# TackBar v0.6.2 — Viewer & Admin Usability Requirements

**Status:** Delivered  
**Scope:** focused usability improvements in the Session Viewer and Admin  
**Baseline:** TackBar v0.6.1 — OVH Mailbox Ingestion  
**Validation:** focused implementation checks for Viewer and Admin increments

---

## 1. Release objective

TackBar v0.6.2 improves inspection of individual sailing metrics and makes
Admin operational status easier to read. The release is intentionally limited
to presentation and derived read-model context; it does not redefine domain,
ingestion or access semantics.

---

## 2. Session Viewer usability

### V6.2-VIEW-01 — Individual SOG + COG analysis

The existing Session Viewer provides an `Individual Analysis` section. Each
selected Activity has exactly one dual-axis time-series chart with SOG in knots
on the primary Y axis and COG in degrees on a secondary Y axis fixed to
0°–360°. With two Activities, the charts and their local presentation state are
independent.

Both series use one GPS/UTC X axis and the current shared Analysis Window.
Existing map, replay and shared `playbackTime` behavior remain unchanged.

### V6.2-VIEW-02 — Temporal chart zoom

Recharts time-series charts support visual temporal zoom and a `Reset` action.
Zoom is presentation-only, uses one local range per chart, and does not modify
Analysis Window, map, Summary, replay or `playbackTime`. No segment or analytics
data is persisted.

COG circular-angle semantics remain unchanged.

---

## 3. Admin Session presentation

### V6.2-ADM-SES-01 — Session lifetime

Admin Session cards show a prominent `ACTIVE` or `EXPIRED` status derived only
from `expires_at` compared with the current time. Active Sessions show the
formatted expiration and whole remaining days; expired Sessions show the
formatted expiration date as expired.

### V6.2-ADM-SES-02 — Capability separation

Shared capability state remains a separate secondary presentation with its
existing Active, Expired, Revoked and Never generated labels. Copy, Regenerate,
Revoke and Renew actions retain their existing behavior. Renewal continues to
replace expiration with the current time plus the selected duration.

---

## 4. Admin Ingestion Sailor status

### V6.2-ADM-ING-01 — Current consent context

Admin Ingestion results expose the current consent state of the Sailor resolved
through the associated Activity. `Result` presents `Sailor status: Pending`,
`Active` or `Revoked`; unresolved results show an unavailable value.

This status is derived at read time and is not persisted as an Ingestion
snapshot. Ingestion processing status remains independently represented as
`Processed` or `Failed`, and the Sailor status does not affect it.

---

## 5. Preserved semantics and non-goals

v0.6.2 preserves:

- Activity identity and persistence;
- Session matching and membership;
- consent lifecycle and ACTIVE-only shared visibility;
- Session capability authorization, expiration and renewal semantics;
- JSON/filesystem persistence behavior;
- ingestion processing, provider boundary and technical status;
- shared Analysis Window, `playbackTime` and replay behavior;
- existing comparison chart behavior;
- COG circular-angle semantics.

The release does not introduce a separate Activity Viewer, new capability or
consent actions, persisted analytics, new ingestion formats, API redesign or
broader Admin redesign.

---

## 6. Validation

Focused Individual Analysis/chart zoom and Admin frontend/backend checks passed,
