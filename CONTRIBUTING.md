# Contributing to TackBar

Thanks for your interest. TackBar is an open-source project running a controlled real-sailing pilot, so contributions are welcome but follow a small process. / Gracias por tu interés. TackBar es un proyecto open-source con un piloto controlado en navegaciones reales, así que las contribuciones son bienvenidas pero siguen un proceso breve.

---

## English

### Reporting a bug or proposing an improvement

1. Search the [open Issues](https://github.com/maxsail-project/tackbar/issues) first.
2. If nothing matches, open a new Issue with the **Product / Engineering Increment** form. It asks for the problem and evidence, the goal, scope and non-goals, and acceptance criteria. Fill in what you know; maintainers refine the rest.
3. Maintainers apply the labels (one of `group:product`, `group:analytics` or `group:operations`, plus `bug` or `research` when it applies) and the `[#id]` title prefix.

An Issue's **Status** describes how well defined the work is. It does not mean the work is approved: implementation starts only after the product owner approves it.

### Pull requests

Please open or comment on an Issue before starting work, so the scope can be agreed first. A pull request should reference its Issue and stay within the approved scope. Behavior is specified in [`docs/current`](docs/current/index.md); changes that alter it should update the matching document.

### Privacy and security

Never put private pilot data in a public Issue or pull request: no participant names or emails, GPS tracks, access links, credentials or tokens. If something could expose participant data or disrupt the service, email [hello@tackbar.eu](mailto:hello@tackbar.eu) instead of opening a public Issue.

### Questions

Project questions: [maxsail.project@gmail.com](mailto:maxsail.project@gmail.com).

## Español

### Reportar un error o proponer una mejora

1. Busca antes en los [Issues abiertos](https://github.com/maxsail-project/tackbar/issues).
2. Si no hay ninguno, abre un Issue con el formulario **Product / Engineering Increment**. Pide el problema y su evidencia, el objetivo, el alcance y lo que queda fuera, y los criterios de aceptación. Rellena lo que sepas; los maintainers completan el resto.
3. Los maintainers aplican las etiquetas (una de `group:product`, `group:analytics` o `group:operations`, más `bug` o `research` si corresponde) y el prefijo `[#id]` del título.

El **Status** de un Issue describe lo bien definido que está el trabajo. No significa que esté aprobado: la implementación empieza solo cuando el product owner lo aprueba.

### Pull requests

Abre o comenta un Issue antes de empezar, para acordar primero el alcance. Un pull request debe referenciar su Issue y ceñirse al alcance aprobado. El comportamiento se especifica en [`docs/current`](docs/current/index.md); los cambios que lo alteren deben actualizar el documento correspondiente.

### Privacidad y seguridad

No publiques datos privados del piloto en un Issue o pull request público: ni nombres o emails de participantes, ni tracks GPS, enlaces de acceso, credenciales o tokens. Si algo pudiera exponer datos de participantes o afectar al servicio, escribe a [hello@tackbar.eu](mailto:hello@tackbar.eu) en lugar de abrir un Issue público.

### Preguntas

Consultas sobre el proyecto: [maxsail.project@gmail.com](mailto:maxsail.project@gmail.com).
